ARRAYS:

1. Why we need arrays:
   → To handle large collection of similar data types
   → It is a data structure to hold data

2. Syntax:
   datatype[] variable_name = new datatype[size];

   Example:
   int[] rollnos = {51, 82, 13, 15, 16};

   OR

   int[] rollnos = new int[5];   // store 5 roll numbers

3. Internal working of array:

   int[] rollnos;    // declaration of array
   → rollnos reference is created in stack

   rollnos = new int[5];   // initialization
   → actual memory allocation happens here
   → object is created in heap memory

   (compile time → declaration)
   (run time → initialization)

   int[] arr = new int[5];

   → datatype: int[]
   → ref var: arr
   → creating object in heap memory

   Above concept is known as Dynamic Memory Allocation


4. Internal Representation of Array:

   In Java, memory allocation depends on JVM whether it is continuous or not.

   Reason 1: Objects are stored in heap memory
   Reason 2: In JLS (Java Language Specification), heap objects are not necessarily continuous
   Reason 3: Dynamic memory allocation, hence array objects may not be continuous (depends on JVM)


5. Index of an array:

   index →   0   1   2   3   4   5
   arr  →   [3,  8,  9, 10, 53, 33]

   arr[0] = 3
   arr[1] = 8
   arr[2] = 9
   arr[3] = 10
   arr[4] = 53
   arr[5] = 33


6. Changing value of array:

   arr[4] = 99;

   New array:
   [3, 8, 9, 10, 99, 33]

NEW KEYWORD IN ARRAY

1. new keyword:
   → Used to create an object

   int[] arr = new int[5];

   → It will create an object in heap memory of array size 5

   If we don’t provide values in array,
   by default it stores:
   [0, 0, 0, 0, 0]   (for int type)

   string[] arr = new String[4];

   → Default values will be null


2. Memory Concept:

   arr → stored in stack (reference variable)

   Actual array/object → stored in heap memory

   Note:
   - Each object can be stored in different parts of heap memory
   - null is a special literal

   Primitive arrays (int, char, etc.) → values stored directly
   Objects → stored in heap memory


3. Arrays to String:

   Arrays.toString(array)
   → Internally uses loop
   → Gives output in proper format

   Example:
   [1, 2, 3, 4]

   Note:
   - Arrays are mutable (we can change values)
   - Strings are immutable

4. 2-D ARRAY:

   Example:

   1   2   3
   4   5   6
   7   8   9

   Declaration:

   int[][] arr = new int[3][3];

   → Row size is mandatory
   → Column size can be given

   OR

   int[][] arr = {
       {1, 2, 3},
       {4, 5, 6},
       {7, 8, 9}
   };


5. Internal Representation:

   → 2D array is "array of arrays"

   arr (stack) → reference

   Heap:
   [
     [1, 2, 3]   → row 0
     [4, 5, 6]   → row 1
     [7, 8, 9]   → row 2
   ]

   arr[0] = [1, 2, 3]
   arr[0][2] = 3

90 = transpose + reverse row
180 = reverse row + reverse column
270 = transpose + reverse col

--------------------------------------------------

6. ArrayList:

   → ArrayList is part of Collection Framework
   → Present in java.util package
   → Provides dynamic arrays
   → Slower than standard arrays (slightly)

   Syntax:

   ArrayList<Integer> list = new ArrayList<>();

   → Uses wrapper classes (Integer instead of int)
   → Can pass initial capacity (e.g., 10)


7. Internal Working of ArrayList:

   → Size is fixed internally

   When arraylist gets full:

   a) Creates new arraylist of larger size
   b) Copies old elements into new arraylist
   c) Deletes old array
