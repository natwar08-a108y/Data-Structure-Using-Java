DISJOINT SET UNION (DSU) / UNION-FIND DATA STRUCTURE
------------------------------------------------------------------------------------------------------------------------------------------------------
Definition:
Disjoint Set Union (DSU), also known as Union-Find, is a data structure used to maintain and manage a collection of disjoint (non-overlapping) sets.

It helps us determine whether two elements belong to the same set and efficiently combine two different sets.

Main Applications:
1. Kruskal's Minimum Spanning Tree Algorithm.
2. Cycle Detection in an Undirected Graph.
3. Finding Connected Components.
4. Network Connectivity.
5. Grouping elements into different components.
---------------------------------------------------------------------------------------------------------------------------------------------------------------
1. BASIC CONCEPT OF DSU
Initially, every element belongs to its own individual set.
Consider 5 vertices:
0    1    2    3    4

Initially, the sets are:
{0}  {1}  {2}  {3}  {4}

Each set has its own representative (leader/root).

For example:
- Representative of {0} is 0.
- Representative of {1} is 1.
- Representative of {2} is 2.

After performing Union(0, 1):
{0, 1}  {2}  {3}  {4}

After performing Union(2, 3):
{0, 1}  {2, 3}  {4}

After performing Union(1, 2):
{0, 1, 2, 3}  {4}

Now vertices 0, 1, 2 and 3 belong to the same set.

Important:
The representative of a set is used to identify that set.
The representative does not necessarily have to be the smallest element.

2. TWO MAIN OPERATIONS OF DSU
A. FIND(x):
Purpose:
Finds the representative (root/leader) of the set containing element x.
Example:

       0
      / \
     1   2
        /
       3

Here:
- Find(0) returns 0.
- Find(1) returns 0.
- Find(2) returns 0.
- Find(3) returns 0.

All these elements belong to the same set because they have the same representative.
How it works:
1. Start from the given element x.
2. Check its parent.
3. Continue moving towards its parent until a node is found whose parent is itself.
4. That node is the representative of the set.

B. UNION(x, y):
Purpose:
Combines the two sets containing elements x and y.

Example:
Initially:
{0}    {1}    {2}    {3}

Perform Union(0, 1):
{0, 1}    {2}    {3}

Perform Union(2, 3):
{0, 1}    {2, 3}

Perform Union(1, 2):
{0, 1, 2, 3}

Important:
- Before combining two sets, find their representatives.
- If both representatives are the same, the elements already belong to the same set.
- Otherwise, combine their sets by connecting one representative to the other.

3. HOW DSU REPRESENTS SETS INTERNALLY

DSU generally uses an array named parent[].

Initially:

parent[] = [0, 1, 2, 3, 4]

It means every element is its own parent and represents its own set.

Now perform Union(0, 1).

Suppose 1 is attached under 0:

       0
       |
       1

parent[] = [0, 0, 2, 3, 4]

Now perform Union(2, 3).

       0       2
       |       |
       1       3

parent[] = [0, 0, 2, 2, 4]

Now perform Union(1, 2).

First, find the representatives:
Find(1) = 0
Find(2) = 2

Attach representative 2 under representative 0:

       0
      / \
     1   2
         |
         3

parent[] = [0, 0, 0, 2, 4]

Now Find(3):
3 → 2 → 0

Therefore, Find(3) returns 0.

Note:
The parent array stores the parent of each node, not necessarily the final representative directly.

4. OPTIMIZATIONS IN DSU

Without optimization, repeated Union operations can create a long chain.

Example:

0
|
1
|
2
|
3
|
4

To find the representative of 4, we may need to travel through multiple nodes.

This can make Find operations slow.

Two important optimizations are:

A. PATH COMPRESSION:

Definition:
Path Compression is an optimization in which every node visited during the Find operation is directly connected to the root/representative.

Before Find(4):

0
|
1
|
2
|
3
|
4

Perform Find(4).

The path is:

4 → 3 → 2 → 1 → 0

After Path Compression:

       0
    / /|\ 
   1  2 3 4

Now every node directly points to 0.

Advantages:
1. Reduces the height of the DSU tree.
2. Makes future Find operations faster.
3. Improves the overall efficiency of DSU.

Important:
Path Compression changes the parent pointers but does not change which elements belong to a set.

B. UNION BY RANK:

Definition:
Union by Rank is an optimization in which the tree with smaller rank is attached under the root of the tree with larger rank.

Rank is an estimate of the height of the tree.

Rules:
1. Find the representatives of both sets.
2. If their ranks are different, attach the lower-rank tree under the higher-rank tree.
3. If their ranks are equal, attach either root under the other and increase the rank of the new root by 1.

Example:

Initially:

{0}    {1}

Both have rank 0.

Perform Union(0, 1).

       0
       |
       1

Rank of 0 becomes 1.

Now consider another set:

       2
       |
       3

Rank of 2 is 1.

Perform Union(0, 2).

Both trees have equal rank.

Attach one root under the other:

         0
        / \
       1   2
           |
           3

Rank of 0 becomes 2.

Important:
- Rank increases only when both roots have equal rank.
- Rank does not always represent the actual height after path compression.
- Rank is maintained as an upper-bound-like structural estimate.

C. UNION BY SIZE:

Definition:
Union by Size is an optimization in which the smaller set is attached under the root of the larger set.

A size[] array stores the number of elements in each set.

Rules:
1. Find the representatives of both sets.
2. Compare the sizes of their sets.
3. Attach the smaller set under the larger set.
4. Update the size of the new representative.

Example:

Set A:

    0
    |
    1

Size = 2

Set B:

    2

Size = 1

Perform Union(0, 2).

Since Set B is smaller, attach it under the root of Set A.

      0
     / \
    1   2

New size of Set A = 3.

Important:
- Size is updated only at the representative/root.
- The size stored at a non-representative node is not used for merging.
- Union by Size and Union by Rank are alternative optimizations.

5. COMPLETE DSU EXAMPLE

Consider 6 elements:

0, 1, 2, 3, 4, 5

Initially:

{0}  {1}  {2}  {3}  {4}  {5}

Operation 1: Union(0, 1)

{0, 1}  {2}  {3}  {4}  {5}

Operation 2: Union(2, 3)

{0, 1}  {2, 3}  {4}  {5}

Operation 3: Union(1, 2)

{0, 1, 2, 3}  {4}  {5}

Operation 4: Find(3)

Find(3) returns the representative of the set containing 3.

Find(3) = Find(0)

Operation 5: Union(4, 5)

{0, 1, 2, 3}  {4, 5}

Operation 6: Find(5)

Find(5) returns the representative of the set containing 5.

Operation 7: Find(0) and Find(5)

If both results are different, they belong to different sets.

Final sets:

{0, 1, 2, 3}    {4, 5}

Total number of disjoint sets = 2.

6. IMPORTANT PROPERTIES OF DSU

1. Disjoint Sets:
- Every element belongs to exactly one set.
- Two different sets never share an element.

2. Unique Representative:
- Every set has exactly one representative/root.
- All elements belonging to the same set return the same representative.

3. Find Operation:
- Find(x) does not change the membership of elements in a set.
- With path compression, it may change the internal parent structure.

4. Union Operation:
- Union combines two different sets into one.
- If both elements already belong to the same set, the number of sets does not change.

5. Number of Sets:
- Initially, with V elements, the number of sets is V.
- Every successful Union operation decreases the number of sets by exactly 1.

6. Tree Representation:
- Each disjoint set is represented as a rooted tree.
- The root is the representative of that set.
- Every node is its own parent at the root.

7. Cycle Detection:
- In an undirected graph, if two endpoints of an edge have the same representative, they are already connected.
- Adding that edge creates a cycle.
- If their representatives are different, adding the edge does not create a cycle.

8. Connectivity:
- Two vertices belong to the same connected component if their representatives are the same after processing the relevant graph edges.

7. TIME AND SPACE COMPLEXITY

Let V = Number of elements.

Without optimization:
- Find operation can take O(V) in the worst case.
- Union operation can also take O(V) because it requires finding representatives.

With Path Compression + Union by Rank/Size:

1. Find:
O(alpha(V)) amortized.

2. Union:
O(alpha(V)) amortized.

Here alpha(V) is the inverse Ackermann function.

It grows extremely slowly and is practically constant for all realistic input sizes.

Space Complexity:
O(V)

Because DSU maintains arrays such as:
- parent[]
- rank[] or size[]

8. DSU IN KRUSKAL'S ALGORITHM

DSU is used in Kruskal's Algorithm to detect cycles efficiently.

Suppose an edge connects vertices u and v.

Step 1:
Find the representative of u.

Step 2:
Find the representative of v.

Step 3:
Compare both representatives.

Condition 1:
If Find(u) == Find(v):
- Both vertices already belong to the same connected component.
- Adding the edge would form a cycle.
- Skip the edge.

Condition 2:
If Find(u) != Find(v):
- Both vertices belong to different connected components.
- Adding the edge will not form a cycle.
- Include the edge in the MST.
- Perform Union(u, v).

Example:

Initially:

{0}  {1}  {2}

Consider edges:

0 ---- 1
1 ---- 2
0 ---- 2

Process edge (0, 1):
Find(0) != Find(1)
Include edge.
Union(0, 1).

Now:

{0, 1}  {2}

Process edge (1, 2):
Find(1) != Find(2)
Include edge.
Union(1, 2).

Now:

{0, 1, 2}

Process edge (0, 2):
Find(0) == Find(2)
Skip edge because it forms a cycle.

Final MST:

0 ---- 1 ---- 2

Number of selected edges = 2 = V - 1.

9. IMPORTANT DIFFERENCE: UNION BY RANK VS UNION BY SIZE

Union by Rank:
- Uses rank[] to decide which tree should become the child.
- Rank represents a structural estimate of tree height.
- Rank increases only when both roots have equal rank.

Union by Size:
- Uses size[] to decide which set should become the child.
- Size represents the number of elements in a set.
- Size of the new root is updated after every successful union.

Both optimizations provide nearly constant amortized operation time when combined with path compression.
